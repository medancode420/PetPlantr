# PetPlantr – Adaptive Hedging, Ops Audit, SSE Polish (v1.0.0‑rc.1)

> GA released: See `v1.0.0.md` for final notes and first‑week watch.

## Summary
- **Ops endpoints (token‑gated via `X-Ops-Token`)**
  - `/api/v1/ops/hedging/config` (GET/POST runtime tuning with clamps)
  - `/api/v1/ops/kill-switch` (enable/disable)
  - `/api/v1/ops/audit/recent` (ring‑buffer audit feed)
- **Adaptive hedging**
  - EMA‑based delay, **max‑parallel‑hedges** cap, per‑minute budget
  - Concurrency‑safe launch gate, idempotency friendly
  - Prometheus: `petplantr_hedge_*` counters/gauges + delay histogram
- **SSE progress**
  - `retry:` hint, **heartbeats**, **Last‑Event‑ID** resume
  - Proper no‑cache/keep‑alive headers
- **Chaos ladder**
  - Converts **upstream** 429/503 to `202 Accepted` with status URL (feature‑flagged)
- **Security & ops**
  - Hardened headers, token‑gated ops, in‑memory audit (+ optional file sink)
  - Guaranteed behavior: internal 429 responses remain 429; only provider 429/503 are converted to 202 via the queue‑ladder handler.
  - ProviderBusy handler: only upstream 429/503 are converted to 202 globally; chaos route supports `?provider=true` to exercise the handler.
- **Tests & CI**
  - Sprint‑C coverage (hedging, SSE, ops, queue ladder)
  - Stable CI via dependency pins and controlled pytest plugin loading

## Upgrade Notes
- **Set `OPS_TOKEN` in production**; all `/api/v1/ops/*` endpoints require `X-Ops-Token` when present.
- **Recommended prod defaults:**
  - `FEATURE_ADAPTIVE_HEDGING=false`
  - `HEDGING_MAX_PARALLEL_HEDGES=1`
  - `HEDGING_MIN_DELAY_MS=300`
  - `HEDGING_BUDGET_PER_MIN=3`
  - `FEATURE_QUEUE_LADDER=true`
  - `FEATURE_SYNTHETIC_MONITOR=true`
  - `FEATURE_CHAOS_TEST=false`
- **Persistence vs runtime:** Ops POST updates apply **at runtime**; restarts revert to env/defaults (use env vars for persistence).

## Monitoring Suggestions (Prometheus)
Alerts

- HedgeWinRateLow: rate(petplantr_hedge_win_total[10m]) / rate(petplantr_hedge_launch_total[10m]) < 0.2 for 10m
- QueueLadderSpike: increase(petplantr_hedge_launch_total[5m]) > 50 for 5m
- SyntheticLatencyHigh: petplantr_synth_last_latency_ms > 1500 for 5m

Observability additions
- New metric: `petplantr_provider_busy_total{phase="create|poll|transport|other",reason="http429|http503|timeout|connect"}` to classify upstream busy/timeout causes. Use it to alert on provider instability and correlate queue ladder activations.

Example alert
```yaml
- alert: ProviderBusySpike
  expr: increase(petplantr_provider_busy_total[5m]) > 20
  for: 5m
  labels: { severity: warning }
  annotations: { summary: "Provider busy/timeout spike – queue ladder may activate" }
```

## Rollback
- Soft: FEATURE_ADAPTIVE_HEDGING=false, or HEDGING_MAX_PARALLEL_HEDGES=0, or raise HEDGING_MIN_DELAY_MS to 1000+
- Queue ladder off: FEATURE_QUEUE_LADDER=false
- Hard: revert the release tag/PR and redeploy

## HTTP Semantics and Headers
- Queue ladder behavior: upstream 429/503 are converted to 202 Accepted with headers; internal 429 remains 429.
- Headers on laddered responses:
  - X-Queue-Ladder: true
  - Retry-After: integer seconds when upstream provides a backoff hint (optional)
  - Location: status URL when provided by the mesh path (optional)
- SSE endpoints set Cache-Control: no-cache, Connection: keep-alive, and include retry and heartbeat frames.

## New/Updated Endpoints
- Mesh generate (internal/e2e): POST `/api/v1/mesh/generate`
  - Purpose: wire the Replicate client to exercise ProviderBusy → 202 laddering and metrics in tests.
  - Returns: 202 with X-Queue-Ladder on provider busy; otherwise standard 200 path.
- Chaos routes (guarded by FEATURE_CHAOS_TEST=true):
  - GET `/api/v1/chaos/force_status?code=429&provider=true|false`
    - `provider=true` simulates upstream 429/503 and exercises the global ProviderBusy handler (ladder → 202).
    - `provider=false` exercises our own 429 path (remains 429; no ladder header).
  - GET `/api/v1/chaos/own429` explicitly returns internal 429 (no ladder header).

## Observability Details
- Labeled ProviderBusy counter in client:
  - Metric: `petplantr_provider_busy_total{phase="create|poll|transport|other",reason="http429|http503|timeout|connect"}`
  - Use cases: alert on upstream instability, correlate with queue ladder rate.
- Queue ladder activation counter (server):
  - Metric: `petplantr_queue_ladder_activated_total`
- PromQL examples:
  - rate(petplantr_provider_busy_total[5m]) by (phase, reason)
  - increase(petplantr_queue_ladder_activated_total[15m])
