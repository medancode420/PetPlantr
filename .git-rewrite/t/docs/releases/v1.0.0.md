# PetPlantr – v1.0.0 (GA)
Adaptive Hedging • Provider‑Only Queue Ladder • SSE Resume • Ops Audit • Production Observability

## Highlights
- **Adaptive Hedging**
  - EMA‑based delay, max‑parallel cap, per‑minute budget
  - Concurrency‑safe launch gate; Prometheus metrics (`petplantr_hedge_*`, delay histogram)
- **Provider‑Only Queue Ladder**
  - Upstream 429/503/timeouts → `202 Accepted` with status URL
  - Header: `X-Queue-Ladder: true` (+ `Retry-After` passthrough when present)
  - **Internal 429s remain 429** (rate‑limit/validation)
- **SSE Polishing**
  - Heartbeats, `retry:` hint, `Last-Event-ID` resume
  - Proper no‑cache / keep‑alive headers
- **Ops & Audit**
  - Token‑gated runtime tuning: `/api/v1/ops/hedging/config`
  - Kill‑switch: `/api/v1/ops/kill-switch`
  - Audit ring buffer (+ optional file sink)
- **Observability**
  - ProviderBusy counters with labels `{phase,reason}`
  - Ladder activation counter
  - Canonical Grafana dashboard + Prometheus alert rules
  - Staging soak reporter + k6 load‑smoke

## Upgrade Notes
- **Prod defaults (recommended)**
  - `FEATURE_ADAPTIVE_HEDGING=false`
  - `HEDGING_MAX_PARALLEL_HEDGES=1`
  - `HEDGING_MIN_DELAY_MS=300`
  - `HEDGING_BUDGET_PER_MIN=3`
  - `FEATURE_QUEUE_LADDER=true`
  - `FEATURE_SYNTHETIC_MONITOR=true`
  - `FEATURE_CHAOS_TEST=false`
- **Security:** set `OPS_TOKEN`, send `X-Ops-Token` for `/api/v1/ops/*`.
- **Runtime vs persistence:** Ops POST applies at runtime; restarts revert to env defaults.
- **Deps:** `numpy==1.26.4`, `httpx==0.27.x` (pytest plugins explicitly loaded in CI).

## Endpoints
- Health: `/api/v1/health`
- SSE demo: `/api/v1/mesh/stream/demo`
- Ops: `/api/v1/ops/hedging/config`, `/api/v1/ops/kill-switch`, `/api/v1/ops/audit/recent`
- Chaos (staging): `/api/v1/chaos/force_status?code=<429|503>&provider=true` (global ladder), `/api/v1/chaos/own429` (internal 429 → stays 429)

## Observability & Dashboards
- **Dashboard (canonical):** `grafana/dashboards/petplantr_hedging_queue_ladder.json`
- **Provisioning:** `grafana/provisioning/{datasources,dashboards}/petplantr.yml`
- **Prometheus alerts:** `petplantr.rules.yml`
- **Key metrics**
  - Hedging: `petplantr_hedge_launch_total`, `petplantr_hedge_win_total`, `petplantr_hedge_delay_ms_bucket`, `petplantr_hedge_skip_*`
  - Provider: `petplantr_provider_busy_total{phase="create|poll|transport",reason="http429|http503|timeout|connect"}`
  - Ladder: `petplantr_queue_ladder_activated_total`
  - Gauges: `petplantr_queue_depth`, `petplantr_tokens_used`, `petplantr_synth_last_latency_ms`

## SLO Baselines
- Breed p95 **< 500 ms**
- Mesh acceptance p95 (202 path) **< 1500 ms**
- Hedge win‑rate **≥ 20%**
- Queue‑ladder activations **< 10%** of mesh traffic
- Synthetic last latency **< 1500 ms**

## Post‑Deploy Validation (copy‑paste)
```bash
# Health
curl -s https://api.petplantr.com/api/v1/health | jq .

# SSE headers (expect 200 + text/event-stream + retry + id)
curl -i https://api.petplantr.com/api/v1/mesh/stream/demo | head -n 15

# Validate alert rules
promtool check rules petplantr.rules.yml
```

## Rollback
- Runtime: `hedging_max_parallel_hedges=0` or raise `hedging_min_delay_ms >= 1000`
- Env: set `FEATURE_ADAPTIVE_HEDGING=false` (and/or `FEATURE_QUEUE_LADDER=false`) then restart
- Hard: revert tag/PR and redeploy
